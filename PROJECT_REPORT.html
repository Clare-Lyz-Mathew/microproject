Abstract

The ESPORTS ARENA is a comprehensive, full-stack tournament management and bracket orchestration platform engineered to streamline the end-to-end administration of competitive electronic sports competitions. Built around a robust relational MySQL architecture and a component-driven React 19 single-page interface, the system eliminates administrative friction by combining multi-game discipline management, real-time single-elimination bracket tracking, live match monitoring, and relational automated progression. By leveraging advanced relational database design—including five interconnected normalized entities, foreign key constraints, cascading triggers, and multi-table INNER and LEFT JOIN aggregations—the platform guarantees absolute data integrity across tournament registrations, match series outcomes, and dynamic leaderboards. The user interface embodies contemporary design principles, offering seamless Cyber Dark and Soft Titanium Light themes, dynamic Challonge-style tree visualizations, and one-click manual winner adjudication that synchronizes instantaneously with the backend database. Furthermore, with built-in offline LAN backup serialization, the application serves both online community leagues and disconnected local area network arena tournaments, delivering an enterprise-grade operational standard for pro esports events.

Project Overview

1. Introduction to the Project

Electronic sports (esports) have experienced explosive global growth, transitioning from informal LAN parties into multi-million-dollar global spectacles with millions of concurrent viewers across titles like League of Legends, Counter-Strike 2, and Valorant. Despite this commercial expansion, amateur organizers, collegiate leagues, and local LAN centers frequently struggle with fragile spreadsheets, manual bracket drawing, and disjointed scorekeeping tools. The ESPORTS ARENA system was conceptualized and developed to bridge this gap, delivering an autonomous, professional, and accessible tournament management platform that couples sophisticated database engineering with intuitive user experience design.

2. Objectives of the Project

  • Automate Bracket Lifecycle Management: Implement deterministic single-elimination tournament trees (Quarterfinals, Semifinals, Grand Finals) with automated winner progression based on relational lineage (next_match_id).
  • Provide Live In-Progress Status Viewing: Allow tournament administrators and spectators to monitor ongoing matches with real-time score counters, map tracking, and dedicated live arena dashboards.
  • Implement Manual Adjudication Controls: Equip referees with one-click manual winner selection buttons that immediately persist match outcomes into the MySQL database and advance teams to succeeding rounds.
  • Showcase Advanced Relational Database Capabilities: Structure normalized tables ensuring referential integrity and execute complex multi-table SQL JOIN queries for live analytics and win-rate computations.
  • Support Disconnected / Offline LAN Arenas: Guarantee zero reliance on external CDNs or cloud assets by utilizing local inline SVG team crests and complete JSON import/export routines.

3. Scope of the Project

The scope encompasses competitive multi-game tournament setups (League of Legends, Counter-Strike 2, Valorant, Rocket League, Dota 2, and Custom Titles), team roster tracking, bracket generation, live match scorekeeping, dynamic leaderboards, and an interactive SQL query inspector. The platform is designed for cross-platform deployment, running seamlessly on local network hosts or distributed web servers.

Key Functional Modules

Module 1: Tournament Lifecycle & Category Management

  • Purpose: Oversees the end-to-end configuration of multi-game esports competitions, ranging from international invitationals to local community LANs.
  • Functionality: Supports multi-game disciplines (LoL, CS2, Valorant, Rocket League, Dota 2, and Custom Titles), single-elimination tree seeding, customizable prize allocations, and date/location scheduling.
  • Inputs: Tournament Name, Game Discipline, Match Format (BO1/BO3/BO5), Prize Pool, Team Seeding, Venue Location.
  • Outputs: New tournament record persisted in tournaments table; auto-generated single-elimination bracket graph with 7 interconnected match entities.

Module 2: Interactive Single-Elimination Bracket Tree Engine

  • Purpose: Renders visual Challonge-style bracket trees illustrating progression from Quarterfinals (Round of 8) through Semifinals to the Grand Finals.
  • Functionality: Displays opposing teams, seeded ranks, official color accents, and live/final map scores. Incorporates an interactive lineage graph where advancing finalists are dynamically rendered upon match conclusion.
  • Inputs: Tournament identifier (tournament_id).
  • Outputs: Responsive SVG/CSS bracket hierarchy with clickable matchup cards and winner highlight badges.

Module 3: Live Arena Monitor & Real-Time Broadcast Hub

  • Purpose: Delivers an dedicated operational monitor for active games currently in progress.
  • Functionality: Provides a "Live Matches Only" filter view with animated pulsing live badges, map score adjustment steppers (+/-), in-game status indicators, and instantaneous winner declaration.
  • Inputs: Live match selection, score adjustment increments.
  • Outputs: Broadcast-grade scoreboard card displaying team crests, live map tallies, and direct match adjudication controls.

Module 4: Manual Winner Selection & Relational Auto-Advancement Engine

  • Purpose: Enables referees to manually designate the match winner and guarantee instant relational progression in the bracket.
  • Functionality: Clicking 👑 Win [TAG] sends a validated PUT request to the API, writing the winning team's ID to winner_id, setting status to completed, and executing a targeted relational update into team1_id or team2_id of next_match_id.
  • Inputs: Match ID, Winner Team ID, Winning Map Scores.
  • Outputs: Synchronized database update across two tables and visual advancement of the winner into the next round match card.

Module 5: Team Roster & Pro Player Management

  • Purpose: Maintains accurate registry data for competitive organizations, team captains, and 5-man pro rosters.
  • Functionality: Tracks player in-game aliases (e.g., Faker, Chovy, ZmjjKK), tactical roles (IGL, AWPer, Duelist, Mid Laner), regional affiliations, and distinctive hex primary colors used to render SVG emblems.
  • Inputs: Team name, 3-character tag, captain name, region, primary color, roster player profiles.
  • Outputs: Relational player records bound via team_id foreign key constraint; dynamic crest generation.

Module 6: Global Standings & Dynamic Win-Rate Aggregation

  • Purpose: Computes cumulative tournament victories, total series played, match wins, and win-rate percentages across all registered squads.
  • Functionality: Utilizes conditional SQL aggregation (CASE WHEN m.winner_id = t.id THEN 1 ELSE 0 END) to compute real-time leaderboards with podium rankings (#1, #2, #3).
  • Inputs: All completed match history records.
  • Outputs: Ranked tabular leaderboard with visual win-rate progress meters and championship accolades.

Module 7: SQL JOINs & Relational Schema Inspector

  • Purpose: Serves as an interactive educational and debugging workbench to showcase database queries in real time.
  • Functionality: Features an SQL query playground with syntax-highlighted SQL scripts, execution time benchmarks in milliseconds, and raw tabular result visualizers.
  • Inputs: Selected query type (Tournaments Overview, Bracket Lineage, Rosters, Standings).
  • Outputs: Formatted JSON payload, query execution time, and rendered table rows.

Multi-Table SQL JOIN Queries Showcase

In strict accordance with the syllabus for 24INMCAL391 (RDBMS Lab), the system avoids data denormalization by utilizing explicit multi-table INNER JOIN, LEFT JOIN, and aggregate query structures.

1. Multi-Table Bracket Match Lineage JOIN Query

Retrieves the complete tournament bracket by joining the matches table with tournaments and three separate instances of the teams table (for Team 1, Team 2, and the declared Winner): 

SELECT 
    m.id,
    m.tournament_id,
    m.round_number,
    m.match_order,
    m.status,
    m.score1,
    m.score2,
    m.scheduled_time,
    m.next_match_id,
    -- Team 1 Information
    m.team1_id,
    t1.name AS team1_name,
    t1.tag AS team1_tag,
    t1.primary_color AS team1_color,
    -- Team 2 Information
    m.team2_id,
    t2.name AS team2_name,
    t2.tag AS team2_tag,
    t2.primary_color AS team2_color,
    -- Adjudicated Winner Information
    m.winner_id,
    w.name AS winner_name,
    w.tag AS winner_tag,
    -- Tournament Metadata
    tr.name AS tournament_name,
    tr.game_title AS game_title,
    tr.match_format AS match_format
FROM matches m
INNER JOIN tournaments tr ON m.tournament_id = tr.id
LEFT JOIN teams t1 ON m.team1_id = t1.id
LEFT JOIN teams t2 ON m.team2_id = t2.id
LEFT JOIN teams w ON m.winner_id = w.id
WHERE m.tournament_id = ?
ORDER BY m.round_number ASC, m.match_order ASC;

2. Global Win-Rate Aggregation Query

Computes real-time win-rates and match win totals by joining teams with tournament_teams and evaluating conditional match victories: 

SELECT 
    t.id,
    t.name,
    t.tag,
    t.captain_name,
    t.region,
    t.primary_color,
    COUNT(DISTINCT tt.tournament_id) AS tournaments_entered,
    COUNT(DISTINCT m.id) AS total_matches_played,
    COUNT(DISTINCT CASE WHEN m.winner_id = t.id THEN m.id END) AS matches_won,
    ROUND(
        (COUNT(DISTINCT CASE WHEN m.winner_id = t.id THEN m.id END) / 
         NULLIF(COUNT(DISTINCT m.id), 0)) * 100, 
        1
    ) AS win_rate_percentage
FROM teams t
LEFT JOIN tournament_teams tt ON t.id = tt.team_id
LEFT JOIN matches m ON (m.team1_id = t.id OR m.team2_id = t.id) AND m.status = 'completed'
GROUP BY t.id
ORDER BY matches_won DESC, win_rate_percentage DESC;

Software Engineering Analysis & Design (24INMCAT307)

1. System Development Life Cycle (SDLC) Methodology

The ESPORTS ARENA platform was developed following an Iterative & Agile SDLC Methodology. Given the dynamic requirements of competitive tournament bracket updates and live score adjudication, the project was segmented into four distinct iterations:

  • Sprint 1 (Architecture & RDBMS Modeling): Schema design in MySQL 3NF, entity relationship modeling, connection pool configuration, and DDL script validation.
  • Sprint 2 (REST API & Relational Auto-Advancement): Development of Express.js backend services, implementation of forward bracket advancement routines, and score update handlers.
  • Sprint 3 (UI/UX Engineering & Bracket Visualizer): Creation of Challonge-style tree layouts, custom CSS tokens, dark/light theme switching, and live match hub integration.
  • Sprint 4 (Historic Esports Seeding & Verification): Integration of authentic world championship brackets (2024 Worlds & Valorant Champions), live status filtering, and end-to-end testing.

2. Feasibility Study

  • Technical Feasibility: The application leverages industry-standard web technologies—Node.js, Express, React 19, and MySQL 8.x. The lightweight bundle size and zero remote image dependencies enable the platform to execute seamlessly on commodity hardware without cloud GPU or external API dependencies.
  • Operational Feasibility: The interface requires zero training for tournament coordinators. Match outcomes and live status updates can be administered through one-click buttons, dramatically reducing manual data entry overhead.
  • Economic Feasibility: Built entirely on open-source frameworks and self-hosted MySQL, the platform incurs zero software licensing costs, making it cost-effective for universities, clubs, and amateur leagues.

User Interface and Design System (24INMCAL393 - UID Lab)

1. UI/UX Design Philosophy

The design system for ESPORTS ARENA rejects cliché, neon-saturated AI palettes in favor of a sleek, high-readability architectural aesthetic inspired by professional tournament platforms such as Challonge, Toornament, and Esports Charts. Key design objectives include:

  • High Contrast & Legibility: Strict typographic hierarchy utilizing modern Google Fonts (Plus Jakarta Sans for headings, Inter for data grids, and JetBrains Mono for technical telemetry).
  • Soft Titanium Slate Light Theme: Rather than using blinding `#ffffff` backgrounds, light mode employs an eye-friendly titanium slate (`#eef2f6` with soft cards `#ffffff` and deep slate `#0f172a` typography) ensuring zero eye fatigue during multi-hour esports tournaments.
  • Cyber Dark Mode: Deep obsidian and gunmetal surfaces (`#0b0e14` and `#121721`) accented with restrained electric cyan (`#38bdf8`) and victory amber (`#f59e0b`).
  • Dynamic SVG Emblems (Zero Asset Failures): To ensure bulletproof offline LAN functionality, teams are assigned unique hex branding colors and acronym tags, rendered locally into crisp SVG vector crests.

Advantages of the System

  • Deterministic Bracket Progression: Eliminates human scoring errors by automatically propagating winning team identifiers along relational foreign key pointers to succeeding rounds.
  • Complete Operational Transparency: Embedded SQL Query Inspector enables students, faculty, and administrators to view the precise SQL join statements executing beneath each view.
  • Bulletproof Offline LAN Capability: Operates completely offline during arena LAN tournaments; zero reliance on cloud CDNs or external image hosts.
  • Live Match Telemetry: Referees can switch any match between Pending, Live, and Completed with single-click manual adjudication.
  • Enterprise RDBMS Integrity: Enforces primary and foreign key constraints, preventing orphaned match entries or conflicting seed numbers.
  • Contemporary Responsive UX: Fluid transitions, eye-friendly light/dark modes, and mobile-friendly layouts ensure usability on smartphones, tablets, and desktop workstations.

Limitations

  • Tournament Structure: Currently optimized specifically for 8-team single-elimination brackets; double-elimination and round-robin group stages require additional junction schema definitions.
  • Manual Player Stats Entry: Player individual statistics (e.g., K/D ratio, headshot percentage) are stored as roster profile metadata rather than granular round-by-round event streams.
  • Single Administrator Session: Authentication currently relies on role-based operational segregation rather than JWT-based multi-user concurrent login sessions.

Future Enhancements

  • Double Elimination & Swiss Formats: Expand the bracket engine to support Lower Bracket runs, Grand Final resets, and Swiss-system qualifiers.
  • Automated Game Server Webhook Integration: Ingest direct game telemetry webhooks from Counter-Strike 2 Game State Integration (GSI) and Riot Games API to update map scores autonomously.
  • Live Stream Embeds: Embed low-latency Twitch, YouTube Gaming, or local RTMP arena video streams directly inside the Live Arena Hub.
  • PDF Certificate Generator: Automatically generate downloadable PDF championship certificates for the winning teams upon conclusion of the Grand Finals.
